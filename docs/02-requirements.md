# 02. 요구사항

> 이 문서는 bookhub가 **무엇을 해야 하는가**를 정의한다.
> 어떻게 구현할지는 다루지 않는다. 엔티티·기술 스택은 [CONTEXT.md](./CONTEXT.md) 참조.

---

## 1. 서비스 개요

bookhub는 도서관의 대출 업무를 전산화하는 시스템이다. 회원은 소장 도서를 검색하고 자신의 대출 이력을 확인하며, 사서는 창구에서 대출·반납을 처리하고 장서를 등록한다.

핵심 설계 전제는 **서지정보(Book)와 물리적 실물(BookCopy)의 분리**다. "해리 포터"라는 책은 하나지만 서가에 꽂힌 실물은 여러 권이고, 대출되는 것은 언제나 특정 한 권이다. 이 구분이 없으면 "3권 중 2권 대출 중"이라는 가장 기본적인 상태를 표현할 수 없다.

대상 사용자는 세 부류다. 도서를 빌리는 **회원**, 창구에서 업무를 수행하는 **사서**, 사서 계정과 조직 차원의 마스터 데이터를 관리하는 **관리자**. 사서는 특정 지점에 소속되며, 자기 지점의 장서와 대출만 다룰 수 있다.

Kotlin + Spring Boot 학습을 목적으로 하는 개인 프로젝트이므로, 실제 도서관 운영에 필요하지만 도메인 모델링의 핵심이 아닌 기능은 의도적으로 제외했다 (→ [5장](#5-1차-범위-제외-항목)).

## 2. 액터 정의

| 액터 | 누구인가 | 소속 지점 | 계정 생성 경로 | 초기 상태 |
|------|---------|----------|--------------|----------|
| **MEMBER** | 도서를 빌리는 일반 이용자 | 없음 (`null`) | 셀프 회원가입 | `ACTIVE` (즉시 이용 가능) |
| **LIBRARIAN** | **특정 지점에 소속되어** 창구에서 대출·반납을 처리하고 그 지점의 장서를 관리하는 직원 | **필수** | 셀프 회원가입(소속 지정) 후 관리자 승인 | `PENDING` → 승인 시 `ACTIVE` |
| **ADMIN** | 사서 계정과 전 지점 공용 마스터 데이터를 관리하는 운영자 | 없음 (`null`) | 초기 SQL (멱등) | `ACTIVE` |

**권한은 누적이 아니라 분기한다.** MEMBER의 이용자 권한(검색·본인 이력·본인 연장)은 세 역할이 공통으로 갖지만, LIBRARIAN과 ADMIN은 서로 포함 관계가 아니다. ADMIN은 사서의 상위 권한자가 아니라 운영을 관리하는 다른 역할이며, 창구 업무는 수행하지 않는다 (→ [P-1](#43-권한)).

여기에 더해 **사서에게는 소속 지점이라는 두 번째 축이 있다.** 역할이 LIBRARIAN이라는 것만으로는 부족하고, 다루려는 대상이 자기 소속 지점의 것이어야 한다 (→ [P-8](#43-권한)). MEMBER와 ADMIN은 소속이 없으므로 이 축의 적용을 받지 않는다.

### UC-06 도서 검색 — 검색어와 필터

| 구분 | 항목 | 설명 |
|------|------|------|
| **검색어** | 제목 / 저자 / ISBN | 입력한 문자열로 서지정보를 찾는다. |
| **필터** | 지점 | 해당 지점에 복본이 있는 Book만 남긴다. |

## 4. 도메인 규칙

### 4.1 대출

| # | 규칙 | 근거 |
|---|------|------|
| L-1 | 대출 기간은 14일이다. | 2주는 한 권을 읽어내기에 충분하면서 장서 회전을 막지 않는 관행적 기준이다. |
| L-2 | 한 회원이 동시에 대출할 수 있는 도서는 3권까지다. | 한도가 없으면 소수 이용자가 인기 장서를 독점해 다른 이용자의 접근권이 사라진다. |
| L-3 | 연체 중인 대출이 1건이라도 있으면 신규 대출을 할 수 없다. | 벌점 제도를 두지 않았으므로(→ [5장](#5-1차-범위-제외-항목)) 반납 유인은 대출 차단뿐이다. |
| L-4 | 연장은 7일씩 최대 2회까지 가능하다. | 무제한 연장은 사실상 반납 기한이 없는 것과 같아 L-1을 무력화한다. |
| L-5 | 연체 중에는 연장할 수 없다. | 기한을 이미 어긴 상태에서 기한을 늘려주면 L-1·L-3의 강제력이 사라진다. |
| L-6 | 대출과 반납 처리는 사서만 수행한다. | 실물 책이 창구에서 오가는 행위이므로, 실물 인수인계를 확인한 사람만 기록할 수 있어야 한다. |
| L-7 | 연장은 회원 본인 또는 사서가 수행한다. | 실물이 오가지 않는 데이터 변경이며, 필요한 검증(소유권·연체·횟수)이 모두 저장된 값으로 판단 가능하다. |
| L-8 | 회원이 연장할 때는 해당 대출이 본인 것인지 반드시 확인한다. | L-7로 연장 경로를 연 대가로, 타인의 대출을 조작할 수 있는 구멍이 생긴다. |
| L-9 | **연체는 상태로 저장하지 않고 계산으로 판단한다.** `status == LOANED && dueDate < 오늘` | 저장하면 배치 실행 시점과 실제 시점 사이에 불일치가 생겨 진실이 두 개가 된다. 연체는 행위로 전이되는 상태가 아니라 시간이 지나면 자동으로 성립하는 조건이다. → [ADR-0007](./adr/0007-overdue-as-calculation.md) |
| L-10 | 대출 대상은 `AVAILABLE` 상태의 복본에 한정한다. | `DAMAGED`·`LOST` 복본은 물리적으로 인도할 수 없다. |
| L-11 | 사서가 자기 소속 지점에서 자신의 대출을 직접 처리하는 것을 막지 않는다. | 역할과 소속 조건을 모두 만족하며, 감사 목적의 자기거래 제한은 1차 범위에서 다루지 않는다. |
| L-12 | 대출은 반납(`RETURNED`) 또는 복본 분실(`LOST`)로 종료된다. 어느 쪽이든 종료일(`closedAt`)을 기록한다. | 분실은 반납과 다른 종료 사유이며, 변상 처리나 통계에서 구분되어야 한다. 연체와 달리 사서의 명시적 판정으로 전이되므로 계산이 아닌 상태로 저장한다 (→ L-9와 대비). |
| L-13 | 대출 대상 회원은 `status`가 `ACTIVE`여야 한다. | M-8에 따라 이 조건이 걸러내는 것은 승인 대기 중인 사서 계정이다. M-3이 `PENDING`의 로그인을 막지만 대출은 사서가 대행하므로 대상 회원의 상태는 별도로 확인해야 한다. |

### 4.2 회원

| # | 규칙 | 근거 |
|---|------|------|
| M-1 | 일반 회원은 가입 즉시 `ACTIVE`가 된다. | 도서를 빌리는 권한에는 조직 차원의 검증이 필요하지 않다. |
| M-2 | 사서는 가입 시 `PENDING`으로 생성되고 관리자 승인 후 `ACTIVE`가 된다. | 사서 권한은 타인의 대출 기록을 변경할 수 있으므로, 셀프 가입만으로 부여되면 누구나 창구 권한을 가져간다. |
| M-3 | `PENDING` 상태에서는 로그인할 수 없다. | 승인 전 계정이 토큰을 발급받으면 M-2의 승인 절차가 형식에 그친다. |
| M-4 | 이메일은 중복될 수 없다. | 로그인 식별자이므로 중복 시 인증 주체가 결정되지 않는다. |
| M-5 | 관리자 계정은 초기 SQL로 멱등하게 생성한다. | 첫 사서를 승인할 주체가 필요한데, 그 주체를 승인해줄 상위 권한이 존재하지 않는 부트스트랩 문제가 있다. |
| M-6 | **LIBRARIAN은 반드시 소속 지점을 가진다. MEMBER와 ADMIN은 소속이 없다 (`null`).** | 사서 권한은 언제나 특정 지점에 대한 권한이다. 소속 없는 사서는 P-8의 검사 대상을 특정할 수 없어 전 지점 권한과 구별되지 않는다. |
| M-7 | **기본 지점을 초기 SQL로 멱등하게 생성한다.** | UC-02(사서 가입)에서 선택할 지점이 최소 하나는 존재해야 한다. 지점 개설은 ADMIN 권한인데(P-5), 지점이 없으면 첫 사서가 가입할 수 없는 두 번째 부트스트랩 문제가 생긴다. |
| M-8 | `PENDING` 상태인 계정은 승인 대기 중인 사서뿐이다. MEMBER와 ADMIN은 생성 시점부터 항상 `ACTIVE`다. | M-1과 M-2에서 따라오는 결론이지만 명시해둔다. 회원 상태를 검사하는 지점(L-13, UC-11)에서 그 검사가 실제로 무엇을 걸러내는지가 이 규칙 없이는 드러나지 않는다. 상태 판정 로직을 읽을 때 "일반 회원도 `PENDING`일 수 있나"를 매번 되짚게 된다. |

### 4.3 권한

| # | 규칙 | 근거 |
|---|------|------|
| P-1 | **권한은 누적이 아니라 분기한다.** MEMBER의 이용자 권한은 세 역할이 공통으로 갖지만, LIBRARIAN과 ADMIN은 서로 포함 관계가 아니다. | ADMIN은 사서의 상위 권한자가 아니라 운영을 관리하는 다른 역할이다. 창구 업무는 현장 사서의 일이며 관리자가 대신 수행할 이유가 없다. |
| P-2 | **공통(세 역할 전부)**: 도서 검색·상세 조회, 본인 대출 이력 조회, 본인 대출 연장 | 세 역할 모두 도서를 빌리는 이용자이기도 하다. 자신의 데이터를 읽고, 실물 이동이 없는 자신의 변경만 수행한다. |
| P-3 | **LIBRARIAN 전용**: 도서 등록, 복본 등록, 복본 파손·수선·분실 처리, 대출/반납 처리, 대출 연장 대행, 지점 대출 현황 조회, 지점 연락 정보 수정 | 창구와 서가에서 실제로 일어나는 일을 기록하는 역할이다. ADMIN은 이 목록을 갖지 않는다. |
| P-4 | **ADMIN 전용**: 사서 승인, 지점 개설, 지점명 수정, 카테고리 생성·수정 | 조직 차원의 결정과 전 지점이 공유하는 데이터만 담당한다. LIBRARIAN은 이 목록을 갖지 않는다. |
| P-5 | **지점 정보는 필드에 따라 수정 권한이 갈린다.** 지점명(`name`)은 ADMIN, 연락 정보(`address`, `phone`)는 소속 LIBRARIAN. 지점 개설은 ADMIN. | 지점명은 조직이 정하는 정체성이고 주소·전화번호는 현장 운영 정보다. 각 정보를 가장 정확히 아는 주체가 다르므로 수정 권한도 나뉜다. ADMIN이 연락처까지 고칠 수 있으면 P-1의 역할 분기가 무너지고, 사서가 지점명을 바꿀 수 있으면 조직 차원의 명칭 체계가 흔들린다. |
| P-6 | 카테고리는 생성·수정 모두 ADMIN. | 전 지점이 공유하는 분류 체계라 개별 사서가 바꾸면 일관성이 깨진다. |
| P-7 | 본인 소유 리소스에 대한 행위는 소유권을 검증한다. (UC-13, UC-15) | 역할 검사만으로는 "MEMBER가 다른 MEMBER의 대출을 연장"하는 경우를 막지 못한다. |
| P-8 | **사서의 권한 검사는 두 층이다** — `역할 == LIBRARIAN` 그리고 `대상의 지점 == 사서 소속`. **LIBRARIAN 전용 규칙이다.** 적용 대상: UC-09, UC-10, UC-10-1, UC-10-2, UC-11, UC-12, UC-14, UC-16, UC-18 | 역할 검사만 하면 A지점 사서가 B지점의 복본을 대출 처리하거나 B지점 정보를 수정할 수 있다. 실물이 있는 곳과 권한이 있는 곳은 일치해야 한다. ADMIN이 이 검사에서 빠지는 것은 제약을 면제받아서가 아니라 P-1에 따라 해당 업무 자체를 수행하지 않기 때문이다(UC-18-1은 적용 대상이 아니다). |
| P-9 | **도서 등록(UC-08)은 소속 지점 제약을 받지 않는다. 소속 제약은 `BookCopy`부터 적용된다.** | `Book`은 전 지점이 공유하는 공통 카탈로그다. 지점마다 같은 ISBN을 중복 등록하면 서지정보가 갈라져 Book/BookCopy 분리의 의미가 사라진다. |

### 4.4 카테고리

| # | 규칙 | 근거 |
|---|------|------|
| C-1 | 카테고리 검색은 하위 카테고리를 포함한다. | 이용자는 "문학"을 찾을 때 그 아래 세부 분류까지 함께 보기를 기대한다. |

### 4.5 복본

| # | 규칙 | 근거 |
|---|------|------|
| B-1 | 복본 상태 전이는 아래 6가지만 허용한다. 그 외 전이는 금지한다. | 정의되지 않은 전이를 허용하면 대출 중인 복본이 파손 처리되어 `Loan`은 `LOANED`인데 복본은 `DAMAGED`인 불일치가 생긴다. |
| B-2 | 파손된 복본은 수선 후 대출 가능 상태로 복귀할 수 있다. | 파손은 물리적으로 회복 가능한 손상이며, 수선 비용을 들인 장서를 영구 폐기하는 것은 낭비다. |
| B-3 | 분실(`LOST`)은 최종 상태이며 다른 상태로 전이하지 않는다. | 분실된 실물은 시스템이 확인할 수 없다. 나중에 발견되는 경우가 있으나 이를 다루려면 되돌리기 유스케이스가 필요해 1차 범위에서 제외한다. |
| B-4 | 대출 중인 복본은 파손 처리할 수 없다. 먼저 반납해야 한다. 단 분실은 대출 중에도 처리할 수 있다. | 파손된 책은 실물이 돌아오므로 반납이 선행 가능하지만, 분실된 책은 반납 자체가 불가능하다. |
| B-5 | 대출 중인 복본을 분실 처리하면 해당 대출도 `LOST`로 종료된다. | 복본만 `LOST`로 바꾸면 대출이 `LOANED`로 남아 회원의 대출 한도를 영구히 점유하고, 기한이 지나면 연체로 신규 대출까지 막힌다. |

## 5. 1차 범위 제외 항목

| 제외 항목 | 제외 이유 |
|----------|----------|
| **예약 / 대기열** | 대출 불가한 복본에 대기를 거는 기능. 순번·만료·알림이라는 별도 상태 기계를 요구하며, 이는 Book/BookCopy/Loan 모델링을 익힌다는 학습 목표와 직교한다. |
| **연체 벌점** | 연체일수에 비례해 이용을 정지하는 제도. L-3(연체 시 대출 차단)이 이미 반납 유인으로 동작하므로, 벌점은 정교화일 뿐 새로운 도메인 개념을 주지 않는다. |
| **지점 간 이동 / 상호대차** | 복본을 다른 지점으로 옮기거나 타 지점 장서를 대출하는 기능. 이동 중이라는 제3의 위치 상태와 지점 간 정산이 필요해 복잡도가 급증한다. |
| **저자 엔티티 분리** | `Book.author`를 문자열이 아닌 엔티티로 승격. 동명이인·공저·번역자를 다루려면 필요하지만, 검색 요구사항이 "저자명으로 찾기" 수준이라 문자열로 충분하다. |
| **연체 상태 전환 배치** | 스케줄러로 `LOANED → OVERDUE`를 갱신하는 작업. L-9에 따라 연체를 계산값으로 다루기로 결정해 배치 자체가 불필요해졌다. → [ADR-0007](./adr/0007-overdue-as-calculation.md) |
| **복본 폐기 / 삭제** | `LOST`·`DAMAGED`로 표시할 수는 있으나 레코드를 지우지는 않는다. 과거 대출 이력이 참조하는 복본을 삭제하면 이력이 깨진다. |
| **비밀번호 재설정 / 이메일 인증** | 인증 부가 기능. JWT 발급·검증이라는 핵심 흐름이 아니고, 외부 메일 발송 인프라를 끌어들인다. |
